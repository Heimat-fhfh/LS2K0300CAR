# 视觉变换坐标映射数组使用说明

## 文件位置

坐标映射数组生成在：

```text
src/vision_transform_coordinate_map.cpp
```

该文件由下面命令生成：

```bash
conda run -n loongCar python test/inverse_perspective_images.py --map-only
```

当 `config/vision_transform.json` 中的逆透视矩阵、输入输出尺寸，或 `config/calibration.yaml` 中的相机标定参数发生变化时，需要重新运行上面的命令。

## 数组名字

所有数组都在命名空间 `vision_transform_coordinate_map` 中。

| 名字 | 类型 | 含义 |
| --- | --- | --- |
| `kMapX[240][320]` | `float` | 输出图每个像素对应的原始输入图 `x` 坐标 |
| `kMapY[240][320]` | `float` | 输出图每个像素对应的原始输入图 `y` 坐标 |
| `kValidMask[240][320]` | `uint8_t` | 坐标是否有效，`1` 表示有效，`0` 表示越界或无效 |

当前尺寸：

```text
输入图像：320 x 240
输出图像：320 x 240
```

数组下标顺序是 `[y][x]`，也就是 `[行][列]`。

## 坐标含义

映射数组已经同时包含：

```text
去畸变 + 逆透视
```

使用时不要再对同一张图重复执行去畸变或逆透视。

对于输出图中的一个像素 `(dst_x, dst_y)`：

```cpp
src_x = kMapX[dst_y][dst_x];
src_y = kMapY[dst_y][dst_x];
```

含义是：输出图的 `(dst_x, dst_y)` 应该从原始输入图的 `(src_x, src_y)` 位置取像素。

如果：

```cpp
kValidMask[dst_y][dst_x] == 0
```

说明这个输出像素没有有效来源，通常填黑色 `0` 或直接跳过。

## 在 C++ 文件中引用

不要 `#include "src/vision_transform_coordinate_map.cpp"`。

在需要使用映射的 `.cpp` 文件中写 `extern` 声明：

```cpp
#include <cstdint>

namespace vision_transform_coordinate_map {
extern const float kMapX[240][320];
extern const float kMapY[240][320];
extern const uint8_t kValidMask[240][320];
}
```

当前 `CMakeLists.txt` 会通过 `file(GLOB SRC src/*.cpp)` 自动编译 `src/vision_transform_coordinate_map.cpp`，所以其它 `.cpp` 中只需要声明，不需要手动加入源文件。

## OpenCV 使用示例

如果输入是 `cv::Mat src`，可以直接把数组包装成 OpenCV 映射表：

```cpp
#include <cstdint>
#include <opencv2/opencv.hpp>

namespace vision_transform_coordinate_map {
extern const float kMapX[240][320];
extern const float kMapY[240][320];
extern const uint8_t kValidMask[240][320];
}

cv::Mat applyVisionCoordinateMap(const cv::Mat &src) {
    using namespace vision_transform_coordinate_map;

    cv::Mat map_x(240, 320, CV_32FC1, const_cast<float *>(&kMapX[0][0]));
    cv::Mat map_y(240, 320, CV_32FC1, const_cast<float *>(&kMapY[0][0]));

    cv::Mat dst;
    cv::remap(
        src,
        dst,
        map_x,
        map_y,
        cv::INTER_LINEAR,
        cv::BORDER_CONSTANT,
        cv::Scalar::all(0));

    return dst;
}
```

灰度图、彩色图都可以这样处理。若输入是二值图，为了保持 `0/255`，建议把 `cv::INTER_LINEAR` 改成 `cv::INTER_NEAREST`。

## 不使用 OpenCV 的最近邻示例

如果后续处理的是二维灰度数组，可以直接按最近邻取样：

```cpp
#include <algorithm>
#include <cmath>
#include <cstdint>

namespace vision_transform_coordinate_map {
extern const float kMapX[240][320];
extern const float kMapY[240][320];
extern const uint8_t kValidMask[240][320];
}

void applyVisionCoordinateMapNearest(
    const uint8_t src[240][320],
    uint8_t dst[240][320]) {
    using namespace vision_transform_coordinate_map;

    for (int y = 0; y < 240; ++y) {
        for (int x = 0; x < 320; ++x) {
            if (!kValidMask[y][x]) {
                dst[y][x] = 0;
                continue;
            }

            int sx = static_cast<int>(std::round(kMapX[y][x]));
            int sy = static_cast<int>(std::round(kMapY[y][x]));
            sx = std::max(0, std::min(319, sx));
            sy = std::max(0, std::min(239, sy));

            dst[y][x] = src[sy][sx];
        }
    }
}
```

如果需要更平滑的灰度或彩色图效果，可以基于 `kMapX/kMapY` 自己实现双线性插值；如果是赛道二值图，最近邻通常更合适。

## 注意事项

1. `kMapX/kMapY` 是从输出坐标反查原始输入坐标，不是把输入坐标正向投影到输出坐标。
2. 数组中的无效坐标会写成 `-1.0f`，使用前优先检查 `kValidMask`。
3. 当前映射来源于 `config/vision_transform.json` 和 `config/calibration.yaml`。
4. 当前使用的是 C++ 数组文件，不再使用 `config/vision_transform_coordinate_map.npz`。
